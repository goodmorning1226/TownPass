# 全功能助理：第一批實作紀錄

2026-11-05，分支 `feat/ai-assistant-plan`，App 基線 `e4fbd3c`。
沿用 Flutter/GetX、TPRoute、原生頁面與既有 WebView bridge；模型仍為 `ministral-3:3b`。

## 已加入

- 共用目錄 `assets/assistant/capabilities.json`：70 個入口／內部能力，涵蓋 21 個城市服務及原生功能。41 個允許開頁，29 個停用並附原因。「允許開頁」不是正式交易能力，也不是所有裝置均已實測成功。
- 問候、不理解、借書教學皆可不跳頁；功能列表由目錄生成，每頁 8 項，可說「下一頁」。輸入「全部功能」相關列表需使用「查看全部功能」，會包含未串接項目。
- 服務名稱、服務關鍵字、內部功能關鍵字共同檢索；精確檢索後才用保守模糊比對，最多提供 5 個精確候選或 3 個模糊候選。Ministral 只選候選內工具，無任意網址、JS 或提交權限。
- 模糊書名、同名系列／作者多本與歧義服務先展示選項。點選或輸入「第幾個」確認後才導頁；數字識別碼不作模糊修正。
- 候選綁定 session、resolution ID、目錄版本，5 分鐘過期；取消、新話題與舊選項重播不會執行。狀態只存本機記憶體，後端重啟會清空。
- 功能目標從 App 內相同目錄解析，不能讓模型提供任意路由。圖書詳情以同一 WebView 先載入總覽，再載入詳情，建立原頁面返回層級，隱藏檢索不加入歷史。
- 每個新的助理導覽會清除 App 主畫面之上的舊頁面，再建立新服務本身的正常父頁；不把前一個助理服務當作上一頁。一般回覆、候選確認、無效或取消的請求不清除目前頁面。
- 原生子頁依登錄的父頁堆疊開啟；費用子服務先切換原繳費頁籤。其他一般開頁流程仍可使用。

## 範圍限制

本批完成 P0/P1、P2 的服務與書目候選確認、P3 導覽機制，以及部分 P4/P5 可用頁面的導入。
尚未完成所有欄位的型別／選項抽取、表單受控預填 adapter、語音、正式會員認證、真實借閱／付款／送件及稽核。
地圖缺金鑰、空回呼、依賴前頁 store、未連正式 API 等功能先停用；相關原因放在共用目錄。
後續加入欄位需另建明確 schema、驗證與確認流程，不可用任意 JS 填表。

## 使用者裝置驗收

後端啟動方式見 [README](../assistant_backend/README.md)。本批有新增 App asset，請 Stop 後重新 Run，單純 hot reload 不足。

| 輸入／操作 | 預期 |
| --- | --- |
| 你好、??? | 短回覆，不跳頁 |
| 有哪些功能 → 下一頁 | 可用功能列表分頁，不自動開啟 |
| 查看全部功能 | 包含未串接狀態，不能點進停用頁 |
| 案件進度 | 多服務候選；確認前不跳頁 |
| 我要看圖書借閱排行 | 原圖書排行頁 |
| 借底層羅輯 | 顯示可能書名，確認後才開詳情 |
| 借神奇柑仔店 → 第二本 | 先選冊，再進對應書籍 |
| 借小紅帽 | 無書目且模型辨識為書籍時回圖書總覽，不開空搜尋 |
| 書籍詳情 → 手機返回／頁面左上返回 | 圖書總覽；再返回回到 App 主畫面 |
| 案件進度 → 助理開圖書 → 按叉叉 | App 主畫面，不回到案件頁 |
| 案件進度 → 助理開圖書首頁 → 手機返回 | App 主畫面，不回到案件頁 |
| 圖書 → 助理開個人資料 → 依序返回 | 設定 → 帳號 → App 主畫面，不回到舊圖書服務 |
| 書籍詳情 → 點原網頁內其他頁 → 返回 | 依該 WebView 正常歷史返回 |
| 候選出現後取消／關閉，重新提問 | 不沿用前一個候選 |
| 開助理後 Android 返回 | 先關助理；不意外退出服務 |
| 掛號／缺 API 功能 | 說明尚未串接，不假裝完成 |

請回報輸入、選項、實際開啟頁面與返回結果。實際 WebView 歷史、遠端頁面可用性和裝置操作尚待此輪驗收。

## 驗證與回復

Python 30 個測試、Flutter 14 個測試通過；另用實際 Ministral 檢查 6 個一般／候選／導頁案例，均符合預期。這些是開發案例，不代表通用準確率。
套件沿用 lockfile；已執行 build_runner 產生碼。Android debug APK 建置通過；Dart App client → HTTP 後端 → 地端模型的中文傳輸測試通過。
本批助理與 WebView 檔案分析無問題；全專案分析為零錯誤、7 個既有 warning、16 個既有 info，因警告而退出碼非零，並非全專案零警告。fluttertoast 的 KGP 未來相容性警告仍存在。
可透過 `--dart-define=ASSISTANT_ENABLED=false` 關閉助理，保留原服務操作；未 push 或修改官方分支。
