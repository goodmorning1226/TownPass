# 助理全螢幕介面、語音與頁面狀態規劃

日期：2026-11-06。狀態：規劃已與使用者確認，尚未實作。
沿用 `ministral-3:3b`、Python 後端、Flutter／GetX、原 WebView 與 [AGENTS.md](../AGENTS.md)。
保留候選確認、取消／遲到回覆防護，以及「新的助理導航先清除舊服務歷史」。
本文件補充 [全功能分步計畫](AI_ALL_FEATURES_ROLLOUT_PLAN.md)，不取代其中的目錄、候選與返回規則。

## 1. 使用者流程

| 步驟 | 畫面 |
| --- | --- |
| 入口 | 右下角按鈕改稱「助理」 |
| 開啟 | 全螢幕微透明背景覆蓋原頁面（原頁面隱約可見、不可操作）；中下方圓形麥克風鈕，右下角鍵盤小圖示 |
| 首次提示 | 本次 App 執行期間尚無對話時，上方顯示「你可以⋯」與 3–4 個範例；範例來自目錄中已啟用的能力，不由模型產生 |
| 輸入 | 預設**按住說話、放開送出**；點鍵盤圖示改為文字輸入，可再切回語音 |
| 對話 | 由上往下排；使用者訊息靠右，助理回覆在其下方靠左（2026-11-06 驗收後由「都靠左」改為左右分開）。每一輪都會回話 |
| 單純回話／補問／不支援 | 留在全螢幕介面 |
| 候選確認 | 在全螢幕介面內以按鈕選擇；選定後才收起並導航 |
| 操作 | 全螢幕介面收起 → 導航到目標（先清舊服務歷史）→ 右下角「助理」旁顯示簡短回覆，數秒後自動消失 |
| 點右下角回覆 | 直接打開全螢幕介面，並捲到這則訊息 |

### 對話紀錄

- 只存在 App 記憶體；App 行程存活期間保留（換頁、收起介面都在），App 被滑掉即清空，不寫入磁碟。
- **不作為模型上下文**。每輪模型只收到本次輸入與第 3 節的結構化狀態。
- 操作類回覆同時寫入紀錄，與右下角提示相同內容。

## 2. 介面原則

- 簡潔易懂：一個主要動作（按住說話），其他次要；文字精簡、字級足夠，不放多餘裝飾或動畫。
- 符合台北通既有風格：使用 `TPColors`、`TPTextStyles`／`TPText`、`TPButton` 等現有元件與配色，不另建全域主題。
- 支援文字縮放、TalkBack Semantics（麥克風鈕、鍵盤切換、關閉、候選按鈕都有可讀標籤）、大按鈕觸控範圍。
- 關閉方式一致：右上角關閉、Android 返回鍵、點背景空白處；關閉即取消進行中的請求，遲到回覆不跳頁。
- 錄音中顯示明確狀態（例如按鈕放大與「放開送出」字樣），可往外滑取消本次錄音。
- 收合時「助理」按鈕不攔截其他觸控，避開 SafeArea、底部導覽與圖書頁固定按鈕。

### V2 實作備註

- 語音尚未開放（`voiceInputAvailable = false`），介面預設開在鍵盤模式；輸入列的麥克風圖示可切到語音版面預覽，
  按圓形鈕只顯示「語音輸入下一階段開放」，右下角鍵盤圖示切回。V3 完成後改為預設語音版面。
- 「你可以說…」範例為 `AssistantViewController.suggestions`，每項標註導向的能力，測試檢查其在目錄中為啟用；
  點範例等同輸入該句，四句均在 live 回歸集中。
- 背景為白色 90% 不透明＋輕微模糊，原頁面隱約可見；顏色與字級沿用 `TPColors`、`TPTextStyles`（對話用 h3）。
- 使用者泡泡靠右（主色底白字）、助理泡泡靠左（白底灰框）；候選按鈕只出現在最新一則回覆，未串接選項不可點。
- 右下提示 8 秒後自動消失；點它開啟對話並捲到該則訊息。對話紀錄最多保留 200 則，只在記憶體中。

### V3 實作與實測（2026-11-06）

- 模型：自行由官方 `model.safetensors`（SHA-256 `c5d952b3…f6b6` 已核對）轉成 CTranslate2 float16，執行時用 GPU `int8_float16`。
  沒有採用他人上傳的轉換檔；轉換只在 repo 外的隔離 venv 進行。
- 架構：`asr_server.py`（faster-whisper，獨立程序，只聽 127.0.0.1:8770）← 主後端 `/v1/assistant/transcriptions` 驗證 WAV 後轉送 ← App。
  手機仍只連 8765；錄音在手機與電腦都只存在記憶體。
- App：預設語音版面（下方三欄：左側保留給語言選擇、中間麥克風、右側鍵盤）；按住錄音、放開送出、往上滑取消；TalkBack 為點兩下開始／再點兩下送出；最長 30 秒、短於 0.5 秒不送。
  權限拒絕、沒聽清楚、語音服務未啟動都會回話並提示改用鍵盤。辨識文字顯示為使用者泡泡後走原文字流程。
- 辨識提示詞：由共用目錄的所有服務名稱組成（含未串接服務）＋「繁體中文」說明，屬領域詞彙，不是例句。
- 吵雜／小聲對策（2026-11-06 使用者在咖啡廳實測後加入）：
  - 辨識改為同一次 beam search 取 5 個候選句，並回報平均 log-prob 與 no-speech 機率。
  - 雜訊（no-speech > 0.6、log-prob < -1.0）或結果幾乎不是中文（如「Thanks you.」）→ 422「沒有聽清楚，請靠近麥克風…」，不送出。
  - 信心中等（log-prob < -0.45 或 no-speech > 0.3），或聽到的句子對不到任何功能 → 回「我聽到「…」，是這句嗎？」，
    按鈕為聽到的原句＋候選句中能對到目錄功能者（最多 3 個）；使用者點選後才送出，不會靜默替換。
  - 錄音時顯示音量條；1.2 秒後仍太小聲提示「聲音有點小，請靠近麥克風說」。
  - 合成測試（語音降為 30% 並加雜訊）：雜訊與靜音全擋下；亂碼句改為確認；但「我要繳水費」在雜訊下仍可能高信心聽成「我要繳學費」並送出，
    信心值擋不住語意合理的錯字，只能靠導頁後的右下提示與返回修正。辨識約 0.35–0.65 秒。
  - 語言選擇延到 V4：模型已固定中文，英文輸出來自雜訊幻覺，加選單本身解決不了。
- 2026-11-06 使用者實測（模擬器＋電腦麥克風、手機熱點環境，音量條約一半）：「我要借書」連續聽成「我們要解釋」「標誌結束」「我要解除」，
  第三次候選出現「我要借書」並由使用者點選送出；確認流程依設計運作，但辨識率不足。另遇模擬器 DNS 無法解析服務網域，
  以 `emulator -avd <AVD> -dns-server 8.8.8.8,1.1.1.1` 重開解決（屬環境問題，非助理程式）。
- 2026-11-06 傍晚診斷（語音規劃暫停，待使用者補測）：
  - 獨立啟動的模擬器若沒加 `-allow-host-audio` 會把麥克風輸入歸零；加上後仍約一半錄音整段為 0，屬模擬器麥克風轉接不穩。
  - App 記錄「按住時間 vs 錄音長度」一致，取樣率正常；仍改為以 48 kHz 擷取再於 App 降到 16 kHz，避免依賴平台轉換。

    （Windows 輸入音量 53%）。補測方向：輸入音量 100%／麥克風增強、改用 AirPods 麥克風、USB 實機。
  - 語音服務可用 `TOWNPASS_ASR_DIAGNOSTICS=1` 每段印出長度、音量、信心等數字（不含錄音與文字），預設關閉。
- 音近直接修正（2026-11-06 使用者決定，取代「一律確認」）：
  - 語音：聽到的句子對不到功能，而同一段錄音只有一個候選句對得到、且分數相差 ≤ 0.5 → 直接送出該句，
    並顯示「我聽到「…」，當作「…」處理；不對的話請再說一次。」（例：「我要結束」→「我要借書」）。
  - 書名：只錯一個字，或讀音相近（如「低曾羅積」→《底層邏輯》）且沒有其他書也像 → 直接開啟並說明；系列書仍請使用者選。

    Unicode License v3），可用 `scripts/extract_unihan_readings.py` 重建；未使用中國開發的拼音工具庫。

## 3. 頁面與動作狀態（送給後端）

App 每次送出時附上固定欄位的狀態；第一版頁面只取路由與 URL：

| 欄位 | 內容 |
| --- | --- |
| `page.type` | `native`／`web`／`tab` |
| `page.route` 或 `page.path` | 原生 GetX 路由（如 `/setting`），或 WebView 服務路徑（如 `/library-service/book-detail/lib-book-3`）；不含 query 中的個資 |
| `last_action` | 上一次助理導航的目的地（搜尋只送類型）、結果（`opened`／`failed`／`cancelled`）與經過秒數 |

- 後端只把狀態當檢索線索（例如在圖書頁說「排行榜」優先圖書），不能據此拼網址、擴大權限或略過候選確認。
- 不傳頁面文字、表單內容、帳號資料或 token。路徑與欄位先過白名單格式檢查，未知值丟棄。
- 已實作為 contract 3：新增選填欄位，舊後端拒收未知欄位，需同時更新兩端。
- 實作調整：能力 ID 由後端依路徑自行對應（App 不送 `capability_id`，避免用戶端自稱位於某頁取得提示）；
  「動作結果回報」併入下一輪請求的 `last_action`，未另開端點；待確認候選後端本來就知道，App 不重複回報。
- 表單填到哪等更細的網頁狀態，需 TownPass-Services 配合，不在第一版。

## 4. 語音辨識

| 項目 | 決定 |
| --- | --- |
| 模型 | 優先 Whisper 微調：**MediaTek Research Breeze-ASR-25**（Whisper-large-v2 微調、Apache-2.0、針對台灣華語與中英混用）。轉換或部署不成功則改用 OpenAI Whisper 原版 |
| 執行 | 在電腦地端，與 Ollama 相同只聽 loopback；Python 後端轉送，手機不直接連辨識服務 |
| 流程 | 按住錄音 → 放開上傳音訊 → 辨識成文字 → 顯示為使用者泡泡 → 走原有文字流程 |
| 隱私 | 音訊只在記憶體處理，不保存、不記錄；新增 Android 麥克風權限，拒絕時改用鍵盤並說明 |
| 錯誤 | 辨識空白／失敗時回話請使用者重說或改打字，不送模型 |

待驗證：Breeze-ASR-25 約 2B 參數，模型頁未提 whisper.cpp 格式，需實測轉換、量化後與 Ministral 共用
RTX 4060 8 GB 的 VRAM、延遲與中文正確率；不足時評估量化或讓辨識走 CPU。
排除中國開發模型（如 SenseVoice、FunASR／Paraformer）。

後續語言：先一般中文；其他語言與台語另立階段。Breeze-ASR-25 模型頁未提台語，
台語需另找非中國開發的模型，並決定輸出漢字或台羅，再處理 3B 模型能否理解。

## 6. 後續功能規劃（2026-11-07 與使用者討論後確認）

順序依「小而立即有感」到「不確定性高」。所有模型仍不可使用中國開發的模型，採用前逐一確認來源與授權。

1. **選項編號與語音選擇（V4）**：候選按鈕與「我聽到…是這句嗎？」選項都標 1、2、3；說或打「1」「二」「第二個」「選第 2 個」
   即選取，並以「第 N 項：…」明確回顯選了什麼。後端原本就支援綁定候選時的序號；App 端在有可選清單時於本地解析序號。
   辨識提示加入序號說法。風險：「一」「二」很短易誤聽，因此選後一定回顯。
2. **朗讀回覆（V5）**：用手機內建文字轉語音（`flutter_tts`），不佔電腦 GPU、支援多語；只唸助理回覆，按麥克風、送出新需求或
   關閉介面時立即停止；預設關閉以免在公共場所自動唸出內容。伺服器端語音合成暫不採用（許多中文 TTS 為中國開發，
   例如 CosyVoice；BreezyVoice 以其為基礎，須先確認主辦單位是否接受）。
3. **預設助理 App（V6）**：宣告 Android ACTION_ASSIST，使用者在系統設定選 TownPass 為預設數位助理後，長按首頁或從角落滑動
   即開啟助理，不需常開麥克風；另可加桌面捷徑。最接近 Siri 的開啟方式且沒有隱私疑慮。
4. **多國語言（V7）**：範圍先限助理介面（整個 App 與 TownPass-Services 網頁多不在本 repo），語言選單放左下保留位置；
   Breeze 主要是華語／英語，其他語言用 OpenAI Whisper 原版；檢索為中文關鍵字，因此外語先由 Ministral 翻成中文
   再走原流程、回覆翻回（每句約多 0.5–1 秒，小語種品質需實測）。待使用者選定語言（如英、日、越、印尼）。
5. **台語（V8）**：Breeze 不支援台語。需調查台灣學界／研究者的台語辨識模型（開發來源、授權、準確率），最好能直接輸出華語，
   否則台文漢字或台羅對 Ministral 不易理解；台語朗讀選項更少。先交調查結果，不直接實作。
6. **喚醒詞（V9）**：App 開著時可用裝置端喚醒詞模型（如 Picovoice Porcupine，需金鑰），代價是麥克風常開、耗電、Android 頂端
   持續顯示麥克風指示，長者可能有隱私疑慮；背景／鎖屏喚醒需常駐通知，系統級喚醒僅限內建助理，不可行。
   先以 V6 取代，使用者確認可接受麥克風常開後才做，且預設關閉。
