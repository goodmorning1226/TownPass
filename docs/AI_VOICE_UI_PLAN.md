# 助理全螢幕介面、語音與頁面狀態規劃

日期：2026-11-06。狀態：規劃已與使用者確認，尚未實作。
沿用 `ministral-3:3b`、Python 後端、Flutter／GetX、原 WebView 與 [AGENTS.md](../AGENTS.md)。
保留候選確認、取消／遲到回覆防護，以及「新的助理導航先清除舊服務歷史」。
本文件補充 [全功能分步計畫](AI_ALL_FEATURES_ROLLOUT_PLAN.md)，不取代其中的目錄、候選與返回規則。

## 1. 使用者流程

| 步驟 | 畫面 |
| --- | --- |
| 入口 | 右下角按鈕改稱「助理」 |
| 開啟 | 全螢幕微透明背景覆蓋原頁面（原頁面隱約可見、不可操作）；中下方圓形麥克風鈕，右下角鍵盤小圖示 |
| 首次提示 | 本次 App 執行期間尚無對話時，上方顯示「你可以⋯」與 3–4 個範例；範例來自目錄中已啟用的能力，不由模型產生 |
| 輸入 | 預設**按住說話、放開送出**；點鍵盤圖示改為文字輸入，可再切回語音 |
| 對話 | 使用者訊息以泡泡排在左上方；助理回覆以泡泡排在該問句下方左側。每一輪都會回話 |
| 單純回話／補問／不支援 | 留在全螢幕介面 |
| 候選確認 | 在全螢幕介面內以按鈕選擇；選定後才收起並導航 |
| 操作 | 全螢幕介面收起 → 導航到目標（先清舊服務歷史）→ 右下角「助理」旁顯示簡短回覆，數秒後自動消失 |
| 點右下角回覆 | 直接打開全螢幕介面，並捲到這則訊息 |

### 對話紀錄

- 只存在 App 記憶體；App 行程存活期間保留（換頁、收起介面都在），App 被滑掉即清空，不寫入磁碟。
- **不作為模型上下文**。每輪模型只收到本次輸入與第 3 節的結構化狀態。
- 操作類回覆同時寫入紀錄，與右下角提示相同內容。

## 2. 介面原則

- 簡潔易懂：一個主要動作（按住說話），其他次要；文字精簡、字級足夠，不放多餘裝飾或動畫。
- 符合台北通既有風格：使用 `TPColors`、`TPTextStyles`／`TPText`、`TPButton` 等現有元件與配色，不另建全域主題。
- 支援文字縮放、TalkBack Semantics（麥克風鈕、鍵盤切換、關閉、候選按鈕都有可讀標籤）、大按鈕觸控範圍。
- 關閉方式一致：右上角關閉、Android 返回鍵、點背景空白處；關閉即取消進行中的請求，遲到回覆不跳頁。
- 錄音中顯示明確狀態（例如按鈕放大與「放開送出」字樣），可往外滑取消本次錄音。
- 收合時「助理」按鈕不攔截其他觸控，避開 SafeArea、底部導覽與圖書頁固定按鈕。

## 3. 頁面與動作狀態（送給後端）

App 每次送出時附上固定欄位的狀態；第一版頁面只取路由與 URL：

| 欄位 | 內容 |
| --- | --- |
| `page.type` | `native`／`web`／`tab` |
| `page.route` 或 `page.path` | 原生 GetX 路由（如 `/setting`），或 WebView 服務路徑（如 `/library-service/book-detail/lib-book-3`）；不含 query 中的個資 |
| `page.capability_id` | App 依目錄反查到的能力 ID，查不到為 null |
| `last_action` | 上一次助理導航的能力 ID、結果（`opened`／`failed`／`cancelled`）與時間 |
| `pending` | 是否有待確認候選（後端本來就有，App 只回報面板狀態） |

- 後端只把狀態當檢索線索（例如在圖書頁說「排行榜」優先圖書），不能據此拼網址、擴大權限或略過候選確認。
- 不傳頁面文字、表單內容、帳號資料或 token。路徑與欄位先過白名單格式檢查，未知值丟棄。
- 需要 contract 升級（新增選填欄位，舊後端拒收未知欄位，需同時更新兩端）；同時補上計畫中的「動作結果回報」。
- 表單填到哪等更細的網頁狀態，需 TownPass-Services 配合，不在第一版。

## 4. 語音辨識

| 項目 | 決定 |
| --- | --- |
| 模型 | 優先 Whisper 微調：**MediaTek Research Breeze-ASR-25**（Whisper-large-v2 微調、Apache-2.0、針對台灣華語與中英混用）。轉換或部署不成功則改用 OpenAI Whisper 原版 |
| 執行 | 在電腦地端，與 Ollama 相同只聽 loopback；Python 後端轉送，手機不直接連辨識服務 |
| 流程 | 按住錄音 → 放開上傳音訊 → 辨識成文字 → 顯示為使用者泡泡 → 走原有文字流程 |
| 隱私 | 音訊只在記憶體處理，不保存、不記錄；新增 Android 麥克風權限，拒絕時改用鍵盤並說明 |
| 錯誤 | 辨識空白／失敗時回話請使用者重說或改打字，不送模型 |

待驗證：Breeze-ASR-25 約 2B 參數，模型頁未提 whisper.cpp 格式，需實測轉換、量化後與 Ministral 共用
RTX 4060 8 GB 的 VRAM、延遲與中文正確率；不足時評估量化或讓辨識走 CPU。
排除中國開發模型（如 SenseVoice、FunASR／Paraformer）。

後續語言：先一般中文；其他語言與台語另立階段。Breeze-ASR-25 模型頁未提台語，
台語需另找非中國開發的模型，並決定輸出漢字或台羅，再處理 3B 模型能否理解。

## 5. 實作階段

| 階段 | 內容 | 驗收 |
| --- | --- | --- |
| V0 | 後端小修（schema、重試、metrics、目錄修正、keep_alive）— 2026-11-06 完成 | 單元 40 個、live 回歸 88/88 |
| V1 | 頁面／動作狀態與結果回報（contract 升級） | wire、單元測試；狀態不擴權 |
| V2 | 全螢幕介面（先只用鍵盤）：首次提示、對話泡泡、候選、收起後右下提示、點提示回到訊息、紀錄保存 | widget 測試＋使用者模擬器驗收 |
| V3 | 一般中文語音：錄音權限、按住說話、上傳、Breeze-ASR-25／Whisper | 辨識 wire 測試、延遲與 VRAM 量測＋使用者實機驗收 |
| V4 | 其他語言與台語 | 另行選型與驗收 |

每階段結束提供輸入、預期頁面與返回結果的驗收表；commit 等使用者同意。
