# 引導助理端到端測試計畫（模擬器）

對象：`feat/guided-assistant-mock` 的引導助理（助理面板 → 後端選頁面與教學元件 → App 在原服務頁上逐步引導）。

- 教學元件現在是每頁一個檔案 `assets/assistant/guide_<page>.json`：library、fees、counter_calling、disaster_report、citizen_report、district_office、police_report、coupon_wallet、subscription。第 2 節（圖書借閱）有逐步的卡片／光圈表；其他頁的步驟表還沒寫（見第 3 節）。
- 沒有引導的入口（原生 `police` 警政頁、`fees.scan`/`fees.tax` QR 相機）只驗證「開頁、沒有光圈與步驟卡」。（`Replies.opensPage`「這個功能還沒有逐步引導，只幫你開頁。」目前在 lib/ 裡沒有被使用。）
- 後端判斷的正確性由 `assistant_backend/eval_guides.py`（真模型）與 `test_guide_eval.py`（假模型）負責；這份計畫只測 App 上實際看到與能操作的東西。每個項目的輸入句子都在 `assistant_backend/data/guide_eval.json` 有對應案例（括號內是案例 id）。

## 0. 準備

1. 電腦端：Ollama 執行 `ministral-3:3b`；助理後端照平常方式啟動（不要動 8765 / 8766 上已在跑的服務，除非測試負責人自己安排）。
2. 模擬器 App 的助理後端位址指向該服務；第一次打開助理會先看到使用教學。
3. 每個情境開始前：關掉助理面板、回到 App 首頁、確認沒有進行中的任務（助理面板沒有任務卡）。需要時重開 App。
4. 記錄：每一步截圖（步驟卡 + 光圈位置），以及後端回覆的 `guide.components` 與 `metrics.route`（可從後端或 App debug log 看）。
5. 卡片標籤格式：`步驟 i / n・動詞`，n 是這次計畫的元件數。下面寫「步驟 i/n」時 n 依計畫而定。
6. 「光圈目標」用 `library_guide.dart` 的 target 名稱（例如 `library.search_entry`），對應原頁面上的元素。

通用檢查（每個情境都要看）：

- 助理面板先回 `openedText`（借書：「好的！已經幫你打開圖書館服務。我們先找到書、預約…」；其他：「好的！已經幫你打開圖書館服務，我會在畫面上一步一步帶你做。」）。
- 頁面開好後出現開場卡，有「開始」與「我自己來」兩個按鈕；**不按就不會自己往下走**。
- 待辦清單第一行是「開啟圖書館服務」，之後每個元件一行；預約流程最後多一行「等通知，到館取書（之後你自己去）」。
- 光圈以外的地方變暗且點不了（`locks`）；點暗處出現「沒關係～我們先點亮起來的地方就好。」，連點 3 次變成「要按亮起來的地方喔。想先自己操作，可以按「暫停」。」。
- 助理**絕不**替使用者點、打字或按預約；預約一定是使用者自己按。
- 唸出卡片（若開啟朗讀）：每張新卡只唸一次。

## 2. 圖書借閱（library-only）

### 2.1 預約一本書（目標 `reserve`，計畫 `open_search, search_keyword, pick_book, choose_branch, reserve`，n=5）

起點：chip「我要借書」；或打字「我想借書」(lib-reserve-want)、「你好我想要借一本書謝謝」(lib-reserve-polite)；語音「嗯我想要那個借書」(lib-reserve-um)。

| 步驟 | 卡片標籤 | 卡片文字（摘要） | 光圈目標 | 完成條件 |
|---|---|---|---|---|
| 1/5 | 步驟 1 / 5・點一下 | 不在館藏查詢分頁時：「先點一下上面的「館藏查詢」。」；否則：「我們先找書！點一下上面的「關鍵字搜尋」。」 | `library.tab_search` → `library.search_entry` | 離開圖書首頁 |
| 2/5 | 步驟 2 / 5・打字 | 框是空的：「點一下框框，打你想找的書名，例如「神奇柑仔店」。」；有字：「打好了嗎？按右邊的放大鏡搜尋。」 | `library.search_row`（熱門關鍵字 `library.hot_keywords` 也可以點，不算點錯） | 網址有 `search=` 且非空，或已在書籍頁 |
| 3/5 | 步驟 3 / 5・選一本 | 有結果：「找到了！上下滑動看看，想借哪一本，點一下書名就好。」；沒結果：「這次沒有找到書。換個書名…重新打字搜尋。」 | 有結果 `library.results`；沒結果 `library.search_row`；**畫面不鎖** | 進入 `/book-detail/` |
| 4/5 | 步驟 4 / 5・選擇 | 「接下來，點這裡選要去哪間圖書館拿書。」→ 清單開著：「點一下你方便去拿書的圖書館。」→ 選好：「選好了！按右上角的「✕」關掉這個視窗。」 | `library.branch_field` → `library.branch_list` → `library.branch_close` | 書籍頁、已選取書館、清單已關 |
| 5/5 | 步驟 5 / 5・確認 | 「最後確認一下：預約《書名》，在「取書館」拿書。沒問題就自己按「預約」喔。」 | `library.reserve` | 出現「預約成功」或「預約失敗」對話框 |

完成卡：成功 →「完成了」「預約好了！這是示範網站，沒有真的送出喔。」；失敗 →「沒有預約成功」「這次沒有預約成功，原因是「…」。可以按「查看預約清單」看看，或換一本書。」

邊界情況：

1. **沒有結果**：步驟 2 打「zzzz」搜尋 → 步驟 3 卡片換成「這次沒有找到書…」、光圈回到搜尋框；改打「神奇柑仔店」→ 卡片換回「找到了！…」。
2. **空白搜尋**：框是空的就按放大鏡（或鍵盤完成鍵）→ 不應前進（網址沒有 `search=` 字串）。注意：`Replies.searchEmpty`「先輸入書名，再按搜尋喔。」目前在 lib/ 裡沒有被使用，記錄實際看到的提示。
3. **按鈕不能按（取書館未選）**：步驟 4 時直接點「預約」區 → 被鎖住並出現點錯提示；預約按鈕應為 disabled 樣式（`reserveEnabled` false）。（`Replies.reserveNoBranch`「先選好取書館，才能按預約喔。」目前沒有被使用。）
4. **對話框**：步驟 4 開取書館清單後不選、直接按 ✕ → 回到「接下來，點這裡選…」；選好後換一間（清單仍可點，`alsoUsable`）→ 卡片仍是「選好了！按右上角的「✕」…」。
5. **不能預約的書**：在步驟 3 選一本頁面寫「本館藏不提供預約」的書 → 卡片：「這本書不能預約喔，頁面上寫「本館藏不提供預約」。按左上角的「‹」回上一頁，換一本書看看。」；畫面**不鎖**、沒有箭頭；按 ‹ 回結果 → 回到步驟 3。
6. **預約被拒**：選一本會失敗的書（例如已預約過／額度滿）→ 完成卡顯示「沒有預約成功」及頁面上的原因；`reserveFailed` 是鎖存值，關掉對話框後完成卡不應變回步驟 5。
7. **離開再回來**：步驟 3 時切到 App 首頁或別的服務 → 引導隱藏；助理面板任務卡顯示「回到借書畫面」/「回到借書」→ 按下回到原頁面、**原進度保留**（不從步驟 1 重來）；再說一次「我要借書」→ 詢問「要回去接著借書嗎？」。
8. **我自己來 → 繼續引導**：開場卡按「我自己來」→ 助理說「好，你可以自己操作。需要我帶你做的時候，點「助理」再按「繼續引導」就可以。」，沒有光圈；自己做到書籍頁後在助理面板按「繼續引導」→ 直接從「選擇取書館」那步開始（前面的步驟因頁面狀態已完成而跳過）。
9. **暫停／結束**：任務中在面板按「暫停引導」→ 光圈消失；按「繼續引導」→ 回到同一步。結束引導 →「好的，引導先結束了…」。
10. **點錯**：每一步點暗處 1 次、3 次，看兩種提醒；換到下一步時提醒立即消失、計數歸零。
11. **返回鍵**：步驟 3 在書籍頁按左上角 ‹ → 回到步驟 3（選一本）；步驟 2 在搜尋頁按 ‹ 回首頁 → 回到步驟 1。Android 系統返回鍵同樣測一次（iOS 用邊緣滑動返回）。
12. **書名直達**：打「我要借底層邏輯」(lib-reserve-title-exact) → 直接開書籍頁；步驟 1–3 應立即視為完成，第一張步驟卡是「選擇」(4/5)。打「幫我借底層羅輯」(lib-reserve-title-typo) → 助理說「已把「底層羅輯」當作《底層邏輯》開啟…」再同上。
13. **系列多本**：打「我想借神奇柑仔店」(lib-reserve-title-series) → 先出現「你要找的是哪一本？」選項；選一本 → 開書籍頁並帶預約引導。
14. **預約步驟沒有「好，我自己按」**：目前 `reserve` 步驟不是 commit 步驟，觀察是否有「先不要／好，我自己按」卡片；若沒有，記錄為現況（不是錯誤），但確認助理沒有自動按預約。
15. **任務中問問題**：步驟 4 點 chip「什麼是館藏？」「下一步要做什麼？」→ 回答後回到同一步，不重來。

### 2.10 任務切換與恢復

1. 借書做到步驟 3 → 在助理說「圖書館有什麼公告」→ 應問「你現在正在預約書籍，做到第 3 步。要先暫停借書，改去看圖書館公告嗎？借書的進度我會幫你留著。」→ 選「先繼續借書」→「好，我們繼續借書。關掉這個畫面就能接著做。」；選「暫停借書，改去…」→ 公告引導開始，之後能「回到借書」並保留進度。
2. 公告完成後 → 若有待接續的任務，問「要回去接著借書嗎？」。
3. 在步驟中關掉 App 再打開 → 觀察任務是否保留（記錄現況）。
4. 網路斷掉時開圖書頁 →「服務頁面打不開，請檢查網路後再試一次。」，任務狀態變結束。
5. 後端關掉時說「我要借書」→ 先出現「（目前連不到助理的模型，先用示範內容回答。）」，再用 App 內建關鍵字（`libraryGoalsFor`）開同一個引導。
